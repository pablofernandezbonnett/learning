# Flutter

Use this block to design a Flutter app whose UI, state, network calls, and platform features have clear owners.

1. [Architecture and state ownership](./01-flutter-architecture-and-project-shape.md): divide a feature into UI, behavior, and data boundaries.
2. [Layout, navigation, and async UI](./02-layout-navigation-and-async-ui.md): handle constraints and user-visible states.
3. [Auth and API behavior](./03-auth-api-and-mobile-boundaries.md): translate session and API outcomes into app flows.
4. [Platform integration and tests](./04-platform-integration-and-testing.md): isolate plugins and test the boundary that can fail.

For records, `Future`, null safety, and JSON syntax, use [Dart](../dart/README.md). For the mobile threat model, use [mobile AppSec](../security/08-mobile-appsec-basics.md).
